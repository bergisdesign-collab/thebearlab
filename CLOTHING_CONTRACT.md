# Контракт одежды (ветка bolvanka ↔ sandbox-order-workbench)

Цель болванки: показать фабрике «одно тело + сменная одежда и обувь из общего склада».
Поэтому одежда — отдельный слой, не часть деталей тела. Claude ведёт слой и образы,
Codex ведёт заявку и лист сборки, читая этот же слой.

## Форма данных (в cfg)

- `cfg.clothes` — массив id надетых предметов одежды/обуви, например `["hoodie","sneakers"]`.
  Пусто = образ «База», тело без одежды. Отдельно от `cfg.acc` (аксессуары).

## Каталог (константа CLOTHES в index.html, владелец — Claude)

Каждый предмет:
```
{ id, label, slot, sku, price, color }
```
- `slot`: `top` | `bottom` | `feet` | `wrist`. В одном slot — один предмет (новый вытесняет старый).
- `sku`: артикул для фабрики, формат `CL-<SLOT>-<NNN>`, например `CL-TOP-001`.
- `price`: цена предмета, рубли, целое.

## Образы (константа OUTFITS, владелец — Claude)

```
{ name, clothes:[id,...] }
```
Стартовые три: «База» (пусто), «Худи» (hoodie + sneakers), «Сарафан» (sundress + boots).
Переодевание = заменить `cfg.clothes` на `clothes` образа, тело не меняется.

## Что обязан видеть лист сборки (Codex)

Для каждого id из `cfg.clothes` в заявку идёт отдельная строка:
`sku · label · slot · price`. Тело мишки — первая строка, одежда — следующие строки.
Так на листе видно: одно тело + N отдельных изделий. Это и есть вопрос фабрике:
можно ли шить тела партией, одежду отдельно, а заказы комплектовать из склада.

## Границы

- Claude не трогает сохранение заявки, корзину и форму доставки — это ветка Codex.
- Codex не меняет CLOTHES и OUTFITS — читает их. Правки каталога — через Claude.
- Обе ветки вливаются в main отдельными PR.
