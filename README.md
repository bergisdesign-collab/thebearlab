# BearLab — мастерская мишки

Совместный frontend-прототип Димы и Ильи: игровой дом, питомец, исходная 3D-мастерская, гардероб, три мини-игры и локальная заявка для производства. Основная игра и её GDD ведутся отдельно.

## Пройти демонстрацию

1. **Кормить**: угостите яблоком и напоите водой. Аватар открывает пять потребностей, отдых, купание, прогулку и игру вместе. **Магазин → Еда, вода и уход** пополняет инвентарь; **Рюкзак** расходует запасы.
2. **Одеть**: семь предметов одежды/обуви и 14 аксессуаров, категории, надеть/снять, отменить примерку. **Готово — домой** возвращает в игру. **Сохранить образ** добавляет сочетание в Коллекцию.
3. Под именем **Выбрать мишку** открывает все 12 пресетов Димы. **События → Салон красок** меняет мех, узор и румянец. **Лаборатория** сохраняет полный исходный конструктор.
4. **Играть**: «Медовые соты» (три в ряд), «Найди пару», «Звёздная тропа». Новый раунд стоит 10 энергии; продолжение после reload бесплатно. Отдых восстанавливает энергию бесплатно. Завершение приносит монеты, звёзды и опыт один раз за раунд. **Рекорды** показывают результаты этого устройства отдельно по каждой игре.
5. **Магазин → Капсула вдохновения** открывает одну из шести палитр за 50 заработанных звёзд. Возможные награды и равные шансы показаны заранее, повторов нет. Начальный демонстрационный баланс не оплачивает капсулы.
6. **Магазин → Собрать физического мишку → В корзину** сохраняет состав, цену и снимок отдельно от редактора. Можно собрать второго мишку, изменить количество или удалить позицию: первая комплектация не изменяется вслед за редактором.
7. **К доставке → Проверить заявку**: выберите получение, заполните учебные поля. Экран проверки показывает состав, сумму, контакты и ограничения. **Подтвердить демозаявку** создаёт локальную запись без оплаты или отправки.
8. **Открыть заявку** показывает состав и шаги сборки. **Скачать JSON** выгружает файл; **Заявки → Открыть файл заявки** импортирует его в другом браузере. Контакты в JSON не включаются.

**⚙ Настройки прототипа**: Студия / Игровой, 2D / 3D, движение, имя, размер, карта экранов. **Тестовое состояние игры** позволяет задать баланс и потребности для проверки крайних сценариев. Это инструменты демонстратора, а не покупка валюты.

**Удобство** на Доме: крупные кнопки, ведущая рука и меньше движения. На компьютере гардероб и игры используют отдельные колонки. В «Три в ряд» стрелки выбирают фишку, Enter/Пробел нажимает; в тропе стрелки двигают персонажа. Alt+1…4 — кормить, играть, одеть, исследовать; Alt+Home — домой. При вводе текста и поверх диалогов горячие клавиши отключены.

Стандартное тело, одежда и аксессуары составляются из 2D-иллюстраций. Произвольная геометрия/цвет используют точный технический снимок с иной художественной манерой. Снимок сохраняется в JSON; в старой нестандартной заявке без снимка остаются точные параметры. Иллюстративная посадка одежды не является производственным лекалом.

Цены, доставка и артикулы демонстрационные; изготовимость подтверждает производство. Нет настоящей оплаты, серверного рейтинга или общей базы заказов. Карта содержит работающие переходы, не полноценный открытый мир. Очистка данных браузера удаляет прогресс. Внешний GLB подходит для локальной примерки, не для передаваемого заказа. Полный контракт с причинами решений и первичными кейсами: [GAME_SCREEN_CONTRACT.md](GAME_SCREEN_CONTRACT.md).

## Запуск и проверки

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Откройте http://127.0.0.1:8000/. Внешние зависимости для запуска не нужны: three.js r147, модель и изображения лежат локально. После первого успешного открытия service worker сохраняет ресурсы для офлайн-работы.

```sh
node --test tests/order-model.test.cjs tests/match3.test.cjs tests/arcade.test.cjs tests/life.test.cjs
```

Браузерные проверки требуют Playwright и Chromium:

```sh
npm install --no-save --package-lock=false playwright@1.63.0
npx playwright install chromium
node tests/browser/run.cjs
```

Runner поднимает собственный локальный сервер и завершает его после проверки. `BEARLAB_BASE_URL` позволяет проверять уже запущенную сборку; `BEARLAB_CHROME` задаёт путь к Chromium; `BEARLAB_PLAYWRIGHT` — путь к установленному модулю. Скриншоты и результаты сохраняются вне репозитория, в системном временном каталоге `bearlab-demo-qa` или в `BEARLAB_QA_DIR`.

Проверяются 360×640, 390×844, горизонтальный 844×390 и desktop 1440×900/1000: игровая композиция, уход, однократные награды, сохранение прогресса, гардероб, карта, полный раунд, переключение в студию; отдельно — две комплектации, количества, доставка, экспорт/импорт в чистый контекст, настройки, 3D, некорректный JSON/код, отказ clipboard и офлайн. Это браузерные размеры, а не испытание на физических телефонах.

## Совместная работа

Одна задача — одна ветка и PR. Ссылка на основную версию https://bergisdesign-collab.github.io/thebearlab/ соответствует `main`; демонстрация ветки указывается отдельно в PR. Агенты не объединяют PR без согласования владельца.

| Файл | Назначение |
| --- | --- |
| `index.html` | Мастерская, 3D, маршруты, match-3, интеграция общего состояния |
| `sandbox/studio-ui.js`, `sandbox/studio-ui.css` | Студия, общие иллюстрации, адаптация, настройки |
| `sandbox/game-ui.js`, `sandbox/game-ui.css` | Игровой слой по референсу №9, локальный питомец, награды, диалоги, гардероб и карта |
| `sandbox/wardrobe-ui.js`, `sandbox/wardrobe-ui.css` | Иллюстрированный гардероб и сохранённые образы |
| `sandbox/arcade-model.js`, `sandbox/arcade.js`, `sandbox/arcade.css` | Три игры, сохранение раундов и локальные рекорды |
| `sandbox/life-model.js`, `sandbox/life-ui.js`, `sandbox/life-ui.css` | Потребности, запасы, экономика, энергия и палитры |
| `GAME_SCREEN_CONTRACT.md` | Назначение экранов, причины решений и критерии проверки |
| `GAME_VISUAL_CONTRACT.md` | Композиция, критерии визуальной приёмки, источники и границы |
| `sandbox/bear-preview.js` | Снимок реальной модели для нестандартной комплектации |
| `sandbox/order-model.js` | Неизменяемые заявки, валидация, совместимость, JSON и хранение |
| `sandbox/workshop.css` | Оригинальная мастерская Димы |
| `sandbox/order-ui.js`, `sandbox/order-ui.css` | Сохранённый первоначальный интерфейс демозаявок |
| `PROTOTYPE_SPEC.md` | Текущий контракт экранов и поведения |
| `tests/` | Проверки модели, игры и браузерных маршрутов |
| `assets/demo/` | Рисованные персонаж и мир — проба, не утверждено |
| `teddy.json`, `vendor/three-r147/`, `sw.js` | Встроенная модель, локальная библиотека и офлайн-кэш |

Каталоги `bot/` и `worker/` — отдельные сервисы; эта демонстрация их не использует.
